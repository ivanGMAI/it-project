# 7 Требования к программному компоненту «Агент»

Структура раздела следует ГОСТ 19.201-78 «Техническое задание. Требования к содержанию и
оформлению». Требования относятся к компоненту «Агент» — части контейнера «API-приложение и
worker агента» (рисунок 10), которая превращает сообщение аналитика в изменение схемы.
Числовые значения взяты из кода schemix: файлы `limits.py` и `main.py` пакета `bpmn_assistant`.

## 7.1 Назначение

Компонент принимает запрос из очереди и строит по тексту сообщения изменение схемы BPMN 2.0.
Он задаёт аналитику уточняющие вопросы, если в тексте не хватает фактов. Рискованное изменение
компонент передаёт на подтверждение с предпросмотром, а безопасное записывает новой ревизией.

Состав компонента показан на UML-диаграмме компонентов (рисунок 12):

- **Worker агента** (`application/agent/worker`) берёт запросы из очереди по аренде;
- **Runner агента** (`application/agent/runner`) ведёт запрос по этапам;
- **Роли агента** (`adapter/agents`) — промпты и JSON-схемы ролей модели;
- **Клиент модели** (`adapter/llm`) — обращения к провайдеру языковой модели.

## 7.2 Функциональные требования

Варианты использования системы показаны на UML-диаграмме вариантов использования (рисунок 11).
Компонент «Агент» реализует варианты «Построить схему по описанию», «Ответить на уточняющие
вопросы», «Подтвердить или отклонить рискованное изменение» и включаемый вариант «Извлечь факты
ролями модели».

| № | Требование |
|---|---|
| Ф-1 | Брать из очереди запрос в статусе `queued` с арендой на 90 с и продлевать её каждые 15 с. Если аренда истекла, запрос должен подхватить другой воркер |
| Ф-2 | Обрабатывать запрос конвейером ролей `intent → entities → entity_match → flow → relation_match → review`. Роль `clarify` формирует вопросы, если `review` или код нашли неоднозначность |
| Ф-3 | Принимать от модели только факты с цитатами по JSON-схеме роли. XML BPMN строит код по набору изменений (ChangeSet) |
| Ф-4 | Проверять цитаты по исходному тексту. Ответ роли, не прошедший схему или проверку цитат, отправлять на исправление владельцу этапа, не больше 2 циклов на этап |
| Ф-5 | Применять ChangeSet к копии схемы, раскладывать элементы и проверять кандидата по XSD OMG BPMN 2.0 и правилам графа |
| Ф-6 | Если фактов не хватает, задавать вопросы с ранжированными вариантами ответа: не больше 3 раундов, не больше 3 вариантов на вопрос |
| Ф-7 | Классифицировать риск кодом по ChangeSet. Рискованное изменение публиковать как предложение с предпросмотром, безопасное — как новую ревизию |
| Ф-8 | Записывать ревизию через compare-and-set по базовой ревизии. Если база устарела, переводить запрос в статус `stale` |
| Ф-9 | Сохранять ответ каждой роли (артефакт) с версиями промпта, модели и JSON-схемы. После ответа на вопрос пересчитывать только затронутые этапы |
| Ф-10 | Публиковать в поток событий диаграммы ход работы, черновик и итог запроса |

## 7.3 Интерфейсы компонента

Предоставляемые и требуемые интерфейсы показаны на рисунке 12.

| Интерфейс | Вид | Операции | Кто реализует |
|---|---|---|---|
| `RunProcessor` | предоставляемый | `process(run_id, lease_token)` | Runner агента |
| `StageAgent` | требуемый | `execute(context, input) → StageResult` | Роли агента |
| `LanguageModel` | требуемый (ролями) | `generate(ModelRequest) → ModelResponse` | Клиент модели: OpenAI-совместимый API или Claude Agent SDK |
| `BpmnService` | требуемый | `inspect`, `prepare_changes`, `validate` | BPMN-модуль |
| `RunCompletion` | требуемый | `complete_text`, `publish_questions`, `publish_candidate`, `fail` | Сценарии (`application/workspace`) |
| `UnitOfWork` | требуемый | репозитории, `commit`, `rollback` | Хранилище (PostgreSQL) |
| `StreamEvents` | требуемый | `publish(repository, event)` | Поток событий |
| `Clock`, `IdGenerator` | требуемые | `now()`, `new_id()` | системные адаптеры |

Компонент зависит только от портов `application/ports`. Направление импортов (адаптеры →
приложение → модели) проверяет архитектурный тест `tests/test_architecture.py`.

## 7.4 Требования к надёжности

- Запрос, не завершённый за 24 ч, истекает. Запрос с истекшей арендой возвращается в очередь
  (`recover_expired`).
- Вызов модели повторяется не больше 2 раз при кодах 429, 500, 502, 503, 504.
- У диаграммы не больше одного активного запроса (частичный уникальный индекс в базе).
- Повторная доставка команды с тем же `Idempotency-Key` не создаёт второго запроса.
- После перезапуска сервиса запрос не теряется. Это проверено E2E-тестом
  `production-restart.spec.ts`.

## 7.6 Условия эксплуатации и технические средства

- Запуск: Docker Compose. Контейнеры: PostgreSQL 16, миграции Alembic, backend (Python 3.12,
  FastAPI), frontend (nginx 1.28).
- Память backend в покое — около 240 МБ. Пилотная ВМ стоит 6 662 ₽/мес, демонстрационная —
  3 426 ₽/мес (по `economics.md`).
- Нужен доступ к OpenAI-совместимому провайдеру модели. Ключ хранится только в окружении
  backend. Без ключа работают редактор, импорт и выгрузка, агент недоступен.

## 7.7 Информационная и программная совместимость

- Результат — XML BPMN 2.0, проходящий XSD OMG; файлы открываются в bpmn.io и Camunda Modeler.
- Провайдер модели — любой с OpenAI-совместимым `chat/completions` и строгим JSON-выводом.
  Проверены DeepSeek V4.1 Flash и Qwen3.6 35B.
- Распознавание речи — OpenAI-совместимый `/audio/transcriptions`, WAV 16 кГц моно.
- XML разбирается без внешних сущностей, DTD и сетевого доступа (защита от XXE).
