# 3 Модель функционирования

Модель функционирования построена в виде диаграмм потоков данных (DFD) в нотации Гейна–Сарсона:

- процесс — скруглённый прямоугольник с номером в верхней полосе;
- хранилище данных — открытый справа прямоугольник с номером D;
- внешняя сущность — прямоугольник с двойной кромкой сверху и слева;
- поток данных — стрелка с подписью.

Копия внешней сущности отмечена косой чертой в углу, копия хранилища — дополнительной чертой в
ячейке номера. Копии позволяют обойтись без длинных пересекающихся линий.

## 3.1 Контекстная диаграмма

Контекстная диаграмма (рисунок 3) показывает систему как один процесс 0 и её обмен данными с
окружением:

- **с аналитиком:** описание процесса, ручные правки, ответы на вопросы, выгруженные файлы;
- **с провайдером языковой модели:** роль и JSON-схема ответа в одну сторону, факты с цитатами в
  другую;
- **с сервисом распознавания речи:** аудио фразы в одну сторону, её текст в другую;
- **с BPMN-редакторами:** выгруженный файл BPMN 2.0.

## 3.2 Диаграмма потоков данных первого уровня

На рисунке 4 процесс 0 разложен на семь процессов:

1. Принять описание процесса: текст, документ или голос.
2. Извлечь факты ролями модели.
3. Собрать изменение и проверить схему.
4. Уточнить и подтвердить изменение с аналитиком.
5. Записать ревизию.
6. Выгрузить схему и проверить оформление.
7. Транслировать события в браузер.

Хранилища D1–D5 соответствуют группам таблиц ER-диаграммы:

- D1 «Диаграммы и ревизии» — `diagrams`, `revisions`;
- D2 «Чаты и сообщения» — `chats`, `messages`;
- D3 «Запросы агенту и артефакты» — `runs`, `run_artifacts`;
- D4 «Уточнения и предложения» — `clarification_rounds`, `proposals`, `previews`;
- D5 «Журнал событий» — `diagram_streams`, `stream_events`.

Диаграмма сбалансирована с контекстной: каждый поток уровня 0 разложен на потоки уровня 1 с теми
же внешними сущностями. По правилам нотации данные не переходят напрямую из хранилища во
внешнюю сущность, поэтому события из D5 аналитик получает через процесс 7.
