# ИТ-проект: материалы по schemix

Описание, модели и диаграммы проекта **schemix** — ИИ-ассистента, который превращает текстовое
описание бизнес-процесса в схему BPMN 2.0. Проект сделала команда GoatWhistle на хакатоне
Интер РАО «ИИ-ассистенты для энергетики» (Codenrock, 2026); код — в репозитории `interrao-hack`.

Все модели построены по реальному коду: схеме БД (миграции `backend/migration/versions`),
модулям бэкенда, портам `application/ports` и документации проекта.

Два готовых PDF:

- **[`schemix-full.pdf`](schemix-full.pdf) — полная версия.** Титул, содержание и разделы 1–8:
  текст на листах A4 по ГОСТ 7.32-2017 (Times New Roman 14 пт, поля 30/15/20 мм, номер страницы
  внизу по центру), рисунки на листах A3 альбомных с подписью «Рисунок N — …».
- **[`schemix-diagrams.pdf`](schemix-diagrams.pdf) — только диаграммы.** Обложка с перечнем
  рисунков и 12 рисунков на A3 без текста.

## Как устроен репозиторий

```text
diagrams/src/   исходники: .drawio (draw.io) и .bpmn (bpmn.io, Camunda Modeler)
diagrams/svg/   вектор для печати и PDF
diagrams/png/   растр 2× для Word и слайдов
docs/           тексты разделов 1–8 (Markdown)
tools/          экспорт и сборка PDF
```

Исходники — сами файлы `.drawio` и `.bpmn`, их правят в редакторе:

- **`.drawio`** — draw.io desktop или app.diagrams.net. Таблицы ER — родные таблицы draw.io, к
  ним можно добавлять строки.
- **`.bpmn`** — bpmn.io или Camunda Modeler. Цвета заданы атрибутами BPMN in Color, редакторы их
  сохраняют.

После правки исходников пересобери материалы:

```bash
cd tools
npm install --silent
node export.mjs          # diagrams/src → svg, png (нужен draw.io desktop; путь — переменная DRAWIO)
node make-pdf.mjs        # schemix-full.pdf и schemix-diagrams.pdf в корне
python check-bpmn.py <путь к interrao-hack>/backend/reference/bpmn/xsd
```

## Оформление

- **Цвет несёт смысл и не спорит с текстом.** Палитра приглушённая, шрифт везде Arial.
  - DFD: процесс — синий, хранилище — бирюзовое, внешняя сущность — песочная, аналитик —
    сиреневый.
  - ER: шапка таблицы окрашена по группе таблиц.
  - BPMN: задачи окрашены по дорожке исполнителя.
  - C4: стандартная схема (человек и система тёмно-синие, внешние системы серые), но
    приглушённая.
- **Линии без пересечений.** На ER, DFD, C4 и UML ни одна связь не пересекает другую и не идёт
  сквозь фигуры. Там, где без этого не обойтись, внешняя сущность или хранилище показаны
  дважды; в легенде DFD это пояснено.
- **ER читается однозначно.** Связь входит в строку внешнего ключа потомка, а `runs ↔ messages`
  нарисованы двумя линиями к разным строкам. Пунктир — логическая ссылка без FK
  (`proposals.preview_id`).
- **Подписи рисунков** оформлены по ГОСТ 7.32-2017, п. 6.5.7: по центру под рисунком,
  «Рисунок N — Наименование», без точки. Сами диаграммы заголовков не содержат.

## Что исправлено по сравнению с первой версией

- **Убраны несуществующие функции.** Выгрузки в EPC и интеграции с Sila Union в коде schemix
  нет: выгрузка идёт только в BPMN, SVG, Markdown и DOCX. Обе функции убраны из всех диаграмм.
- **DFD:**
  - хранилище D2 «Чаты и сообщения» только принимало данные и ничего не отдавало, что нарушает
    нотацию; добавлен поток «текст сообщения» в процесс 2;
  - ответы аналитика теперь пишутся в D4 (`clarification_rounds`) и оттуда читаются процессом 2.
- **BPMN 3.** В ветке «только для чтения» была задача «доработать схему», хотя такая схема не
  редактируется. Ветки разведены по коду: диаграмма, ревизия и чат создаются в обоих случаях.
- **BPMN 2.** При ручной правке активный запрос агента не всегда устаревает: готовое
  предложение сначала пытаются перенести на новую ревизию (`invalidate_active_run`).
- **BPMN 1 и 2.** Неявные слияния стрелок заменены XOR-шлюзами.
- **ER «воронья лапка».** У `proposals.preview_id` снят бейдж FK: ограничения FK в базе нет.
- **Добавлено:** пункты 7 и 8 (требования, UML, оценка качества) и развёрнутое описание
  предметной области.
